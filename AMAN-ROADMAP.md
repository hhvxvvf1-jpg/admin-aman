# AMAN Admin — remaining work before full platform control

This is a product and deployment checklist, **not a declaration of completion**. Existing, exercised functions and limitations are recorded in `ADMIN.md` in [`amanapp`](https://github.com/hhvxvvf1-jpg/amanapp). GitHub Pages is a read-only public preview; all operational controls below belong on the authenticated Node service. The Windows package is single-operator and local; it does not provide an online staff service.

| Workstream | Already available | Remaining acceptance work |
|---|---|---|
| Public site and CMS | Localized general/program articles, workflow, scheduled publication, one PNG per general item, saved versions | Managed homepage, menus, footer and policy/reference sections without changing existing identity; verified source/evidence workflows; secure documents; managed video; retention and permanent erasure policy |
| Safeguarding | Assignment/group scoping, private audio, referrals and case activity | Supervised recipient-specific information sharing, approved case retention/blocking, independent safety review; validate access and opt-in channels before enabling real intake |
| Girls | Self-declared band, scoped CMS/search and approved quizzes | Verified age assurance, enforcement across every delivery surface, and independent review of appropriate content; emergency access stays open |
| People and partners | MFA, operational invitations, role ceilings, partner evidence and directory moderation | Trusted recovery procedures, account activity export/privacy review, institution governance, and supervised partner assignment |
| Notifications and community | In-app staff notices and moderation | Opt-in external delivery with safe contacts, revocable preferences and generic previews; member identity controls and pre-publication moderation |
| Assistant and reporting | Approved public sources, multilingual controls and aggregates | Governed knowledge review, independent evaluation and privacy analysis for new breakdowns; no automated safeguarding decisions |
| Finance and operations | Ledger, protected reports, incident workflow and encrypted recovery | Accounting reconciliation if needed, external alerting and scheduler, rehearsed recovery and immutable audit outside the app |
| Hosting and compliance | Node deployment templates and private local install | Dedicated HTTPS host and durable storage, secrets/backup custody, independent security and safeguarding review, and applicable Law 09-08/CNDP procedures before real sensitive data |

Priority for online rollout: (1) select a controlled persistent host and test access/recovery with fictional data; (2) finish public-site CMS, trusted workflows and safety/privacy reviews; (3) enable sensitive or outbound workflows only after their approvals and independent tests pass. Do not move the admin backend, credentials, or operational data to GitHub Pages.
